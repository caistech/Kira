# KIRA — P0.3-B Canonical Persistence Model

**Status:** Implementation Architecture
**Purpose:** Translate the semantic model into concrete persistence entities, identifiers, temporal structures, relationships, and constraints
**Scope:** Canonical entities and their persistence semantics (implementation-independent schema design)
**Prerequisite:** P0.3-A (Implementation Traceability & Gap Matrix)
**Date:** 26 August 2026

---

## 1. Purpose

The purpose of this artifact is to translate the canonical semantic model into concrete persistence structures. It defines how each canonical entity, relationship, and invariant will be represented in the persistence layer.

This is NOT a SQL DDL. It defines the **semantic persistence model** — the entities, attributes, relationships, temporal structures, and constraints that the implementation must satisfy.

The governing principle is:

> **The persistence model must faithfully represent the canonical model. If the canonical model says it, the persistence model must encode it.**

---

## 2. Identifier Conventions

All entities use UUID primary keys. All UUIDs are generated by the database (not by the application). All UUIDs are version 4 (random).

| Convention | Rule |
|------------|------|
| Primary key | `{entity}_id UUID PRIMARY KEY DEFAULT gen_random_uuid()` |
| Foreign key | `{referenced_entity}_id UUID REFERENCES {referenced_table}({referenced_entity}_id)` |
| Temporal columns | `created_at TIMESTAMPTZ DEFAULT NOW()`, `updated_at TIMESTAMPTZ DEFAULT NOW()` |
| Temporal range | `valid_from TIMESTAMPTZ`, `valid_to TIMESTAMPTZ` (for temporal entities) |
| Status | `status TEXT` with CHECK constraint per entity |
| Soft delete | `deleted_at TIMESTAMPTZ` (NULL = active, non-NULL = deleted) |

## 3. Core Entity Definitions

### 3.1 Organisation

**Purpose:** The enduring business entity that owns organisational intelligence.

**Persistence structure:**

| Column | Type | Constraint | Description |
|--------|------|------------|-------------|
| `organisation_id` | UUID | PK | Unique identifier |
| `legal_name` | TEXT | NOT NULL | Legal name of the business |
| `abn` | TEXT | UNIQUE | Australian Business Number (if applicable) |
| `entity_type` | TEXT | CHECK | Legal entity type (sole_trader, company, partnership, trust, etc.) |
| `industry` | TEXT | NULLABLE | Industry classification |
| `status` | TEXT | CHECK, DEFAULT 'active' | Organisation lifecycle state |
| `created_at` | TIMESTAMPTZ | DEFAULT NOW() | When the Organisation record was created |
| `updated_at` | TIMESTAMPTZ | DEFAULT NOW() | When the Organisation record was last updated |
| `deleted_at` | TIMESTAMPTZ | NULLABLE | Soft delete timestamp |

**Status lifecycle:**
```
active → dormant → sold → merged → closed
```

**Constraints:**
- `legal_name` is required (NOT NULL)
- `abn` is unique (if provided)
- `status` is one of: active, dormant, sold, merged, closed
- Only one Organisation can be `active` at a time (business constraint, not database constraint)

**Migration mapping:**
- `users` table → new `organisations` table (backfill from `business_identity`)
- `business_identity.legal_name` → `organisations.legal_name`
- `business_identity.abn` → `organisations.abn`
- `business_identity.entity_type` → `organisations.entity_type`
- `business_identity.industry` → `organisations.industry`

### 3.2 Person

**Purpose:** A distinct human identity that may participate in one or more Organisations.

**Persistence structure:**

| Column | Type | Constraint | Description |
|--------|------|------------|-------------|
| `person_id` | UUID | PK | Unique identifier |
| `email` | TEXT | UNIQUE, NOT NULL | Contact email (not auth) |
| `first_name` | TEXT | NULLABLE | First name |
| `last_name` | TEXT | NULLABLE | Last name |
| `phone` | TEXT | NULLABLE | Phone number |
| `status` | TEXT | CHECK, DEFAULT 'active' | Person lifecycle state |
| `created_at` | TIMESTAMPTZ | DEFAULT NOW() | When the Person record was created |
| `updated_at` | TIMESTAMPTZ | DEFAULT NOW() | When the Person record was last updated |
| `deleted_at` | TIMESTAMPTZ | NULLABLE | Soft delete timestamp |

**Status lifecycle:**
```
active → inactive → deceased
```

**Constraints:**
- `email` is required and unique (contact email, not auth email)
- `status` is one of: active, inactive, deceased
- Person identity persists independently of any Organisation, Membership, or Auth Credential

**Migration mapping:**
- `users` table → new `persons` table (backfill from `users`)
- `users.email` → `persons.email`
- `users.first_name` → `persons.first_name`
- `users.last_name` → `persons.last_name`

### 3.3 Auth Credential

**Purpose:** An authentication mechanism that allows a Person to authenticate to a Kira Instance.

**Persistence structure:**

| Column | Type | Constraint | Description |
|--------|------|------------|-------------|
| `auth_credential_id` | UUID | PK | Unique identifier |
| `person_id` | UUID | FK → persons(person_id), NOT NULL | The Person this credential belongs to |
| `auth_provider` | TEXT | CHECK, NOT NULL | Authentication provider (email, google, magic_link, api_key) |
| `auth_user_id` | TEXT | NOT NULL | The provider's user identifier |
| `status` | TEXT | CHECK, DEFAULT 'active' | Credential lifecycle state |
| `last_used_at` | TIMESTAMPTZ | NULLABLE | When the credential was last used |
| `created_at` | TIMESTAMPTZ | DEFAULT NOW() | When the credential was created |
| `updated_at` | TIMESTAMPTZ | DEFAULT NOW() | When the credential was last updated |
| `deleted_at` | TIMESTAMPTZ | NULLABLE | Soft delete timestamp |

**Status lifecycle:**
```
active → suspended → revoked
```

**Constraints:**
- `person_id` is required (credential belongs to a Person)
- `auth_provider` + `auth_user_id` is unique (one credential per provider per user)
- `status` is one of: active, suspended, revoked
- Revoking a credential does NOT destroy Person identity

**Migration mapping:**
- `users.auth_user_id` → new `auth_credentials` table (backfill from `users`)
- `users.auth_provider` → `auth_credentials.auth_provider`
- Link to Person via `person_id` (backfilled from `users`)

### 3.4 Organisation Membership

**Purpose:** A recorded relationship between a Person and an Organisation, defining roles and temporal scope.

**Persistence structure:**

| Column | Type | Constraint | Description |
|--------|------|------------|-------------|
| `membership_id` | UUID | PK | Unique identifier |
| `organisation_id` | UUID | FK → organisations(organisation_id), NOT NULL | The Organisation |
| `person_id` | UUID | FK → persons(person_id), NOT NULL | The Person |
| `role` | TEXT | CHECK, NOT NULL | Role within the Organisation |
| `status` | TEXT | CHECK, DEFAULT 'active' | Membership lifecycle state |
| `valid_from` | TIMESTAMPTZ | NOT NULL | When the membership started |
| `valid_to` | TIMESTAMPTZ | NULLABLE | When the membership ended (NULL = active) |
| `created_at` | TIMESTAMPTZ | DEFAULT NOW() | When the record was created |
| `updated_at` | TIMESTAMPTZ | DEFAULT NOW() | When the record was last updated |

**Role types:**
```
owner, consultant, introducer, employee, advisor, admin
```

**Status lifecycle:**
```
active → suspended → ended
```

**Constraints:**
- `organisation_id` + `person_id` + `role` is unique (one role per person per organisation)
- `valid_from` must be before `valid_to` (if provided)
- `status` is one of: active, suspended, ended
- Only one membership can be `active` for a given person+role+organisation at a time

**Migration mapping:**
- `users` table → new `organisation_memberships` table (backfill from `users`)
- `users.id` → `membership_id`
- `users.id` → `organisation_id` (via backfilled Organisation)
- `users.id` → `person_id` (via backfilled Person)
- Role derived from context (owner for business users, admin for admin users)
- `users.created_at` → `valid_from`

### 3.5 Ownership Period

**Purpose:** A temporal record of who owned or controlled an Organisation during a specific period.

**Persistence structure:**

| Column | Type | Constraint | Description |
|--------|------|------------|-------------|
| `ownership_period_id` | UUID | PK | Unique identifier |
| `organisation_id` | UUID | FK → organisations(organisation_id), NOT NULL | The Organisation |
| `person_id` | UUID | FK → persons(person_id), NOT NULL | The Person who owned during this period |
| `status` | TEXT | CHECK, NOT NULL | Ownership period status |
| `valid_from` | TIMESTAMPTZ | NOT NULL | When ownership began |
| `valid_to` | TIMESTAMPTZ | NULLABLE | When ownership ended (NULL = current) |
| `transition_context` | TEXT | NULLABLE | How ownership changed (sale, succession, death, etc.) |
| `created_at` | TIMESTAMPTZ | DEFAULT NOW() | When the record was created |
| `updated_at` | TIMESTAMPTZ | DEFAULT NOW() | When the record was last updated |

**Status lifecycle:**
```
current → historical
```

**Constraints:**
- Only one Ownership Period can be `current` for a given Organisation at a time
- `valid_from` must be before `valid_to` (if provided)
- `status` is one of: current, historical
- Historical Ownership Periods are never destroyed
- Ownership change does not destroy Organisation identity

**Migration mapping:**
- `users` table → new `ownership_periods` table (backfill from `users`)
- `users.id` → `organisation_id` (via backfilled Organisation)
- `users.id` → `person_id` (via backfilled Person)
- `users.created_at` → `valid_from`
- Status = 'current' for all migrated records

## 5. Non-Negotiable Persistence Rules

1. **Organisation is the persistence anchor.** All organisational knowledge, memory, genome, and intelligence FK to `organisation_id`, not `person_id`.

2. **Person persists independently.** Person identity persists when membership ends, auth credential changes, or ownership period ends.

3. **Temporal entities have valid_from/valid_to.** Ownership Period, Membership, Kira Instance, Subscription, Commercial Arrangement, and Engagement all have temporal range columns.

4. **Only one current record per temporal relationship.** Only one Ownership Period, Membership (per role), Kira Instance, Subscription, and Commercial Arrangement (per type) can be `active` or `current` at a time.

5. **Historical records are never destroyed.** Ownership Periods, Memberships, Kira Instances, Subscriptions, and Commercial Arrangements are never deleted. They transition to historical status.

6. **Soft delete for Person and Organisation.** Person and Organisation use `deleted_at` for soft delete. All other entities use status transitions.

7. **UUID primary keys.** All entities use UUID v4 primary keys generated by the database.

8. **Audit timestamps.** All entities have `created_at` and `updated_at` timestamps.
