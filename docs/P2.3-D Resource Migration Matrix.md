## Execution Order (Dependency-Respecting)

1. **Phase 0 — Auth Security** (P0)
   - Enable RLS + policies on `auth_credentials`, `organisations`, `persons`

2. **Phase 1 — Core Org Resources** (P1)
   - Enable RLS on `ownership_periods`, `subscriptions`, `commercial_arrangements`, `kira_instances`, `kira_agents`
   - Migrate `business_identity` → retire
   - Migrate `kira_knowledge` / `kira_instances` / `kira_agents` / `conversations` / `decisions` / `drive_documents` (add `organisation_id` NOT NULL, remove `user_id`)
   - Migrate legacy valuation/client/beta tables (add `organisation_id`, remove `user_id`)

3. **Phase 2 — Legacy Knowledge Retirement** (P1)
   - Retire `genome_entities`, `genome_facts`, `genome_relationships`, `genome_events` (P0.7 verified 0 rows)
   - Retire `business_identity`

4. **Phase 3 — Audit/Log Resources** (P1)
   - Migrate `audit_log`, `kira_logs` (add `organisation_id`, RLS)

5. **Phase 4 — Verification & Cascade** (P2)
   - Verify RLS cascade on all child tables (`*_history`, `*_participants`, `*_chunks`, etc.)
   - Run full conformance test suite
