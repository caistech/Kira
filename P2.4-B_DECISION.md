# P2.4-B Decision Artifact — Canonical Ownership of business_valuations

**Date:** 2026-08-29
**Authority:** Canonical Organisational Model (INV-001, INV-020), Phase 4 Audit, P2.4-A Classification
**Scope:** `business_valuations` table + `business_valuation_snapshots` table

---

## Decision

**A Business Valuation is owned by the Organisation.**

| Property | Value |
|----------|-------|
| **Canonical Owner** | Organisation (`organisation_id` NOT NULL, FK to `organisations`) |
| **Provenance** | Person (`person_id` — who commissioned/updated the valuation) |
| **Legacy Column** | `user_id` — deprecated ownership column; retained temporarily for back-compat if needed, not authoritative |
| **RLS Scope** | Organisation-scoped (`auth_user_has_organisation_access(organisation_id)`) |
| **Migration Status** | **DB migration applied** (20260828001718 + 20260828010000); **app code partially rebound** |

---

## Evidence

### 1. Canonical Model
- **INV-001 (Organisation Persistence):** Organisation is the enduring subject; valuations must survive owner/consultant/engagement changes.
- **INV-020 (Organisational Subject Primacy):** Organisational knowledge (valuations, memory, genome) is anchored to Organisation.
- **Phase 4 Audit F4:** "Subscription is org-anchored at schema but the live billing data boundary resolves subscription state via the legacy users table keyed by personId, marked 'P2.4 will migrate'." Valuation is in the same category.

### 4. Valuation History Semantics
- `business_valuation_snapshots` is **append-only time series** carrying `model_version` + `inputs` for recomputability and defence (FINANCIAL_DATA_SCOPE.md §4.1).
- Snapshots already accept `organisationId` in the writer (`lib/valuation/snapshots.ts`).
- The history is **organisational evidence** — it records the business's valuation trajectory, not a person's.

### 5. Introducer / Admin Usage
- `introducer_owner_projection()` (SECURITY DEFINER) reads snapshots via `user_id` join but returns **movement, not rows** — operational proxy, not ownership.
- `lib/admin/exec.ts` builds exec cohort from `business_valuations.user_id` — operational reporting, must pivot to org-scoped via membership.

5. **`lib/onboarding/gate.ts`** — Ensure valuation existence check uses org context.
6. **RLS verification** — Confirm policies work with new query patterns (they already reference `organisation_id`).
